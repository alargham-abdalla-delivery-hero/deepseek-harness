- [x] 4.2 Implemented one React component per curated vocabulary component. **Revised**: does not call `defineComponent`/`createLibrary` at runtime — `COMPONENTS: ComponentRenderers<OpenUIComponent>` (a plain typed object literal) already gets the same "every curated name needs a value" exhaustiveness check from the type annotation alone, at zero runtime cost. An earlier version did call `dsh-openui-lang`'s `buildLibrary()` here purely for that check; removing it cut the browser bundle from 238.65 kB to 8.50 kB (confirmed via a real `tsdown --env.DSH_BUILD_FACE client` build) since it stopped pulling `@openuidev/lang-core`'s runtime into the browser.
- [x] 4.3 Registered a `tool.call.toolview` keyed to `render_ui`. **Revised, materially**: does not use `@openuidev/react-lang`'s `<Renderer>` at all (verified it only accepts raw text and re-parses client-side — the opposite of design.md's "client never re-parses" decision). Instead reads `(block as ToolResultNode).meta` (populated by `dsh-tool-openui`'s `output.presentationMeta`, verified end-to-end against the real wire path) and walks it with a small hand-rolled recursive renderer (`renderElement`). An element outside the curated set renders a visible `Unsupported UI element: <name>` fallback.
- [x] 4.4 `RenderUiView`/`renderElement` are pure functions of `block`/the element tree only — no I/O, no session reads, no clock/random.
- [x] 4.5 Component tests (`@testing-library/react`, jsdom): every curated component renders (including nested Card/Stack), the unknown-component fallback, pending/error/success `RenderUiView` states, the slot registration. 14 tests, 100% coverage.
